## Архитектура: работа без интернета (п. 8)

Сейчас вход сделан через Clerk — это облачный сервис, без интернета не работает.
Рекомендуемая схема:

- **Локальный сервер в ресторане** (мини-ПК, Docker: приложение + PostgreSQL). Все устройства
  (кассы, планшеты кухни/бара, телефоны) работают с ним по Wi-Fi/LAN — интернет для работы не нужен.
- **Свой вход** (логин/пароль + PIN-код для кассиров) вместо Clerk.
- Функции, которым нужен интернет (Telegram, ИИ, облачная копия), работают через очередь:
  пропал интернет — копится, появился — отправляется.
- Ежедневная резервная копия базы на внешний носитель/облако.

## Этапы

0. **Фундамент** — ✅ свой вход (логин/пароль, сессии, сброс и смена пароля, вход в Telegram-бот с паролем),
   ✅ фирменный стиль по брендбуку (#831F21, логотип, Montserrat вместо Museo Sans до покупки лицензии),
   ✅ подразделения (Основной склад, Бар, Кухня, Кондитерская, Хозчасть, Инструменты, Стройматериалы, Зал),
   ✅ работа по локальному адресу сервера (исправлен CORS). ✅ единицы учёта г / кг / мл / л / шт.
1. **Склад и тех-карты** — бар, кухня, кондитерка, хозчасть: номенклатура, приход, перемещения,
   списания, инвентаризации, тех-карты с полуфабрикатами, калькуляция себестоимости.
   ✅ Тех-карты: блюда и полуфабрикаты (вложенные), брутто → нетто → выход с % холодных и тепловых
   потерь, пересчёт г↔кг / мл↔л, себестоимость, наценка, фудкост, «сколько порций можно приготовить»
   из остатков подразделения и что закончится первым, печать тех-карты, защита от циклов.
   ✅ Акт производства полуфабрикатов: предпросмотр списания с остатками и нехваткой, фактический
   выход, сырьё списывается с подразделения, полуфабрикат приходуется отдельной позицией склада
   (создаётся автоматически) по средневзвешенной цене; отмена акта с возвратом сырья и цены.
   Полуфабрикат на складе учитывается в «сколько порций можно приготовить».
   ✅ Инвентаризация подразделения: лист пересчёта по категориям, ввод факта в любой совместимой
   единице (г/кг, мл/л), расхождения в количестве и деньгах (цены фиксируются на начало), поиск и
   фильтры, добавление позиции, бланк для печати; при проведении применяется «факт − учёт» к текущему
   остатку (движения во время пересчёта не теряются); одна открытая инвентаризация на подразделение;
   считает повар/бармен, проводит менеджер.
   ✅ Автосписание по тех-картам при продаже (см. этап 2).
2. **Касса** — меню, продажи, чеки, штрих-коды, смены, автосписание по тех-картам, движение денег.
   ✅ Точки продаж (бывшие «домики») с меню; позиция меню = тех-карта, товар со склада или услуга;
   меню из тех-карт в один клик; штрих-коды и поиск на кассе.
   ✅ Продажа списывает продукты по тех-карте со склада подразделения (готовые полуфабрикаты — с их
   остатка), товар — со склада точки; все списания записываются (база для фактической себестоимости).
   Продажа не блокируется нехваткой — остаток уходит в минус и виден на складе.
   ✅ Цена берётся из меню на сервере; свободная цена — только администратор.
   ✅ Возврат: сумма с учётом скидки чека, безнал не уменьшает наличные в кассе, возврат по закрытой
   смене — из текущей; можно вернуть продукты на склад, если блюдо не готовили.
   ✅ Отчёт «Маржа продаж»: выручка после скидок и возвратов, фактическая себестоимость по списаниям,
   маржа и фудкост по позициям, категориям и дням; предупреждение о позициях без тех-карты.
   ✅ Чек на термопринтер 80/58 мм (печать из браузера, логотип, «не является фискальным»).
   Дальше: фискализация (если нужна).
3. **Отчёты и контрагенты.**
   ✅ Справочник контрагентов: компании и люди, роли (поставщик / клиент / услуги / специалист, можно
   несколько), категории, контакты (звонок и Telegram в один клик), ИНН, реквизиты, условия оплаты,
   оценка, заметки; поиск по названию, телефону (без учёта пробелов), ИНН, заметкам; архив.
   ✅ Карточка: сумма и период поставок, что поставляет и по какой последней цене, последние поступления.
   ✅ Поставщик в приходе выбирается из справочника (или добавляется прямо оттуда); старые текстовые
   поставщики перенесены в справочник миграцией.
   ✅ Журнал складских движений (stock_ledger) ведёт сама база триггером на остатках: любое изменение
   записывается с видом операции, документом и автором; сумма журнала = текущий остаток.
   ✅ Сводные отчёты: движение товара по графам (приход, перемещения, производство, продажи, списания,
   инвентаризация) с расшифровкой каждой операции; остатки на любую дату; закупки по поставщикам;
   деньги по сменам (нал/безнал, возвраты, инкассация, ожидалось/факт/расхождение); выгрузка в Excel (CSV).
   ✅ Исправлено: Telegram-бот менял только общий остаток (его операции затирались) — теперь через склад
   подразделения сотрудника (или основной склад) и с записью в журнал.
4. **Персонал** — ✅ карточки (отдел, ставка час/смена, PIN, аккаунт CRM, согласие на фото), график смен
   по неделям с копированием, киоск отметок на планшете (PIN + фото с камеры, защита от двойного нажатия
   и подбора PIN), табель (по графику/факт, опоздания, ранний уход, переработки, прогулы, «забыл отметить
   уход», начисление, выгрузка CSV), ручные исправления с причиной и журналом аудита. Фото хранятся
   на сервере в `DATA_DIR` (в Docker — том app-data). Камере нужен https или localhost.
   Дальше: распознавание лица локально в браузере (без подписок), уведомления о неявке в Telegram.
5. **Задачник и запрос денег.** ✅ Задачник: исполнитель — карточка сотрудника; статусы Новая → В работе →
   На проверке → Выполнена (или сразу «Выполнено», если проверка не нужна); вернуть на доработку и отменить —
   только с комментарием; чек-лист (исполнитель лишь отмечает пункты); зона ресторана (для будущей 3D-модели);
   повтор каждый день/неделю/месяц — следующая копия создаётся при выполнении; Telegram: новая задача,
   сдана на проверку, возвращена, комментарий, просрочка (раз в 10 минут). Эффективность: доля задач,
   сданных до срока (ожидание проверки не в счёт), опоздания, просроченные, возвраты.
   ✅ Запросы денег: три вида — под отчёт, оплата по счёту (контрагенту), компенсация по чекам.
   Смета по позициям или сумма; согласуют управляющие (свой запрос — нельзя, кроме владельца), можно
   урезать сумму; выдаёт/оплачивает бухгалтер (наличными, переводом, картой, с платёжкой); по подотчёту —
   отчёт чеками (фото/PDF сжимаются на телефоне), 3 дня на отчёт, бухгалтер принимает или возвращает,
   система считает остаток к возврату или перерасход к выплате. Вкладка «Подотчёт» — у кого сколько
   денег на руках. Telegram: новый запрос → управляющим, согласован → бухгалтерии, выдан/оплачен/отклонён
   → сотруднику, отчёт сдан → бухгалтерии. Все действия в журнале аудита. Файлы — в DATA_DIR/money.
6. **Telegram-бот** — новые функции с ролями.
7. **Бронь.** ✅ Календарь броней по столам (таймлайн дня и список), столы и зоны, автоподбор стола под
   компанию (в т.ч. объединение столов), защита от двойной брони (блокировка), статусы визита,
   предоплата (QR / перевод / наличные — отмечает администратор), уведомления менеджерам в Telegram.
   ✅ База гостей: телефон в едином формате (0555… = +996…), Instagram/WhatsApp, день рождения, метки,
   заметки, VIP / чёрный список, история броней, визиты, неявки, внесённые предоплаты.

### 7а. ИИ-агент для переписок и звонков (добавлено)

Цель: ИИ отвечает в WhatsApp, Instagram и по телефону — консультирует по меню, принимает брони,
выставляет предоплату, зовёт менеджера; в CRM — раздел наблюдения за агентом.

- **Ядро — готово:** агент на Claude API (по умолчанию Opus 5.5, можно Sonnet/Haiku) с инструментами:
  меню и цены, свободные столы, создание/перенос/отмена брони через тот же сервис, что CRM, заметки
  в карточке гостя, «позвать менеджера». Сумму предоплаты считает система, лимит гостей для ИИ,
  защита от «чужих» броней. Ошибка ИИ → гостю вежливый ответ, менеджерам — уведомление в Telegram.
  Нужен ключ `ANTHROPIC_API_KEY` в `.env` сервера.
- **Раздел «ИИ-агент» — готово:** все диалоги по каналам, карточка гостя рядом с перепиской, ошибки агента,
  важные сообщения (жалобы, крупные брони, просьба человека), перехват диалога менеджером, статистика
  (диалогов, броней, расход), настройки (тон, правила предоплаты, часы работы, база знаний), тестовый чат.
- **Каналы (следующий шаг):** WhatsApp Business Platform и Instagram Messaging API (официальный доступ Meta; нужен бизнес-
  аккаунт Meta — у ресторана пока только приложения). Звонки — мобильный номер с переадресацией на
  IP-телефонию с голосовым ИИ (распознавание речи → агент → синтез речи).
- **Важно для локального сервера:** сообщения от Meta и телефонии приходят из интернета, поэтому нужен
  защищённый внешний адрес (туннель к серверу ресторана) и интернет для ИИ; без интернета CRM работает,
  а агент — нет.
